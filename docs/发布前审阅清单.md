# Git 发布前审阅清单

本清单的完成不等同于发布授权。只有维护者明确确认仓库可见性、许可证、第三方义务和发布内容后，才可以初始化、提交或推送 Git。

## A. 内容剥离

- [ ] `git status --ignored` 中没有 Vault、`state/`、`www/cache/`、`demo_vault/`、备份或日志。
- [ ] 不存在 `.env`、API 密钥、私钥、截图或个人审查报告。
- [ ] `rg -n -i "password|secret|api[_-]?key|token|cookie|authorization"` 的命中均经人工审阅；示例、变量名和安全文档可保留，真实值不可保留。
- [ ] `python tests/test_release_hygiene.py` 通过。

## B. 可移植性

- [ ] `.env.example` 中只包含占位路径，没有真实用户名、Vault 名称或密钥。
- [ ] 新机器按 README 能完成 `pip install -r requirements.txt`、`npm ci`、`npm run build`。
- [ ] `BRAIN_WEB_VAULT` 已替代机器专属路径；不配置时服务会明确失败而非读取默认个人目录。
- [ ] `frontend/package-lock.json` 与 `package.json` 的本地 `memory-graph` 路径一致。
- [ ] 手动验证启动、停止、索引构建、Obsidian API Key 安装提示和 OCR 安装提示。

## C. 功能与安全

- [ ] `node tests/test_lib.mjs` 通过。
- [ ] `npm run build` 通过，且 `www/` 仍未被加入 Git。
- [ ] 门户仍仅监听 `127.0.0.1`；未加入公网反向代理、端口转发或远程访问说明。
- [ ] 未恢复任何读取或持久化 Obsidian 密钥的端点/代码。
- [ ] REST API 验证在备份 Vault 后执行，确认测试临时笔记已清理。

## D. 法务与第三方

- [ ] 决定并替换根目录 `LICENSE`；未决定前不要将仓库公开。
- [ ] 复核 `THIRD_PARTY_NOTICES.md`、`tools/memory-graph/LICENSE`。
- [ ] 复核 Tesseract 语言数据的再分发条件；需要时附上完整许可证文本。
- [ ] 生成依赖清单/SBOM，并评估 `npm audit` 与 Python 依赖风险。
- [ ] 明确 Obsidian 插件的使用条款由使用者自行遵守。

## E. Git 操作（仅在维护者批准后）

```powershell
git init
git branch -M main
git add README.md LICENSE THIRD_PARTY_NOTICES.md RELEASE_MANIFEST.md .gitignore .env.example requirements.txt docs frontend scripts tests tools serve_portal.pyw 启动门户.bat 停止门户.bat
git diff --cached --check
git diff --cached
git status
```

人工检查暂存差异后，再创建一个只包含发布候选内容的首提交。不要执行 `git add .`，不要推送前先把仓库设为公开，不要强推含凭证的历史。
