# 本地知识门户操作手册

## 1. 安全模型和数据位置

系统分为三层：Vault 保存你的 Markdown 与附件；门户读取 Vault 并提供本机界面；Obsidian Local REST API 负责需要 Obsidian 的读写/检索能力。门户只监听回环地址，不能视为公网服务。

必须位于仓库外：Vault、API 密钥、`.env`、日志、缓存与备份。发布候选包不附带任何这些内容。

## 2. 首次安装

1. 安装 Obsidian 与 Python 3.11+。
2. 双击 `启动门户.bat`。脚本会自动创建 `.venv`、在没有有效 `BRAIN_WEB_VAULT` 时创建 `demo_vault`，并打开浏览器。基础门户预览不需要联网安装 Python 第三方依赖。
3. 默认访问 `http://127.0.0.1:8765/`；若 8765 被占用，脚本会自动尝试 8766、8767 等后续端口。
4. 若候选包没有 `www/` 构建产物，脚本会现场构建前端；此时还需要 Node.js 20+ 与 npm。
5. 需要连接真实 Vault 时，将 `.env.example` 复制为 `.env`，设置：

   ```ini
   BRAIN_WEB_VAULT=C:\Users\YOUR_NAME\Documents\My-Obsidian-Vault
   ```

6. 需要编辑、全文检索与 Obsidian 写入时，在 Obsidian 安装 Local REST API 插件，保持其监听在 `127.0.0.1:27123`，然后在门户“设置”页粘贴密钥。

发布候选版默认不要求门户访问口令。若要启用本机口令保护，在 `.env` 同时设置 `BRAIN_WEB_PORTAL_AUTH=1` 与至少 16 位的 `BRAIN_WEB_PORTAL_TOKEN`。若显示 Obsidian 未连接，检查插件是否启动、端口是否占用，以及设置页密钥是否正确。

屏幕框选 OCR 与 REST 验证脚本依赖 `requirements.txt`。需要这些能力时，可在 `.env` 设置 `BRAIN_WEB_INSTALL_OPTIONAL_DEPS=1` 后重新运行启动脚本，或手工执行 `.venv\Scripts\python.exe -m pip install -r requirements.txt`。

## 3. 日常使用

- **日记/看板/浏览**：编辑经 Obsidian Local REST API 写入。两个门户标签页会对同一路径串行化；外部 Obsidian 修改仍可能触发冲突提示，应先确认再保存。
- **图谱与总览**：运行 `python scripts/build_index.py` 更新。脚本只扫描五个 PARA 分区的 Markdown，生成 `www/cache`。
- **图书馆**：电子书位于 Vault 的 `03-资源/电子图书馆`；读书笔记写到 `03-资源/读书笔记`。笔记用完整 `source` 路径关联，歧义同名书不会自动猜测。
- **OCR**：首次使用会加载仓库内的中英文 Tesseract 语言数据；截图仅在本机浏览器与门户进程之间处理。
- **停止服务**：使用 `停止门户.bat`，不要通过结束不明进程或批量杀 Python 进程的方式处理。

## 4. 备份与恢复

1. 修改 Vault 前，先用 Obsidian 的同步/版本工具或文件级备份保护 Vault。
2. 修改脚本或升级依赖前，保留可运行的 Git 提交或压缩包。
3. `state/` 和 `www/cache/` 可由 `build_index.py` 重建；不要把它们当成唯一数据源。
4. `state/` 与 `www/cache/` 可重建；确认不再需要诊断日志后再清理，不要批量清理未知目录。

## 5. 计划任务建议

计划任务属于系统配置，不随仓库发布。建议先手动验证以下命令，再按你的时区、账户和备份策略创建任务：

- `python scripts/build_index.py`：每小时或按需。
计划任务应使用固定 Python 路径，可通过 `BRAIN_WEB_PYTHON` 指定；任务账户必须能访问 Vault，但不应具有不必要的管理员权限。

## 6. 故障排查

| 现象 | 检查与处理 |
|---|---|
| 门户无法启动 | 检查 Python 是否可用、依赖是否安装成功、`.env` 的 `BRAIN_WEB_VAULT` 是否存在；若启用了 `BRAIN_WEB_PORTAL_AUTH=1`，再检查访问口令是否至少 16 位。 |
| 页面没有图谱/统计 | 运行 `python scripts/build_index.py`，检查 Vault 分区名称和 `state/build_index.log`。 |
| Obsidian 未连接 | 确认插件运行于回环地址，重新粘贴 API 密钥；不要把密钥写入前端源码。 |
| 保存出现冲突 | 重新加载，人工合并后再保存；不要用强制覆盖掩盖外部修改。 |
| OCR 失败 | 检查 `frontend/public/tessdata` 是否在构建产物中、浏览器是否允许本地截图。 |

## 7. 验证

```powershell
node tests/test_lib.mjs
python tests/test_release_hygiene.py
Push-Location frontend
npm run build
Pop-Location
```

如需 REST API 验证，先备份 Vault，再运行 `python scripts/verify_rest_api.py --key-file <仓库外密钥文件>`。
