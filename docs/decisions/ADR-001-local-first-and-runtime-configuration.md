# ADR-001：本地优先与运行时配置

## 状态

接受。

## 日期

2026-08-10

## 背景

系统处理日记、笔记、图谱和书库。原始本地部署包含个人 Vault 路径、构建缓存、日志、备份与仓库外本地前端依赖；直接发布会泄露内容、无法在其他机器复现，并混淆源码和运行数据。

## 决策

1. 发布包只包含源码、最小第三方源码、文档、模板和测试；所有用户数据与运行产物由 `.gitignore` 排除。
2. Vault 和可选 Python 解释器通过环境变量注入，主要变量为 `BRAIN_WEB_VAULT`、`BRAIN_WEB_PYTHON`。
3. 门户继续仅绑定 `127.0.0.1`。发布候选版默认关闭门户口令，便于安装 Obsidian 后本机一键预览；如需保护，可通过 `BRAIN_WEB_PORTAL_AUTH=1` 与 `BRAIN_WEB_PORTAL_TOKEN` 启用受限会话。不提供公网部署配置。
4. 内置前端所需的 `memory-graph` MIT 源码，避免依赖发布仓库之外的绝对路径；Git 版不内置外部云笔记同步。
5. 未验证授权来源的个人背景图片不再分发，候选版使用 CSS 背景。

## 备选方案

### 直接将原工作目录初始化为 Git 仓库

拒绝。该目录包含数据、缓存、备份和历史凭证风险，审查范围不可控。

### 只写 `.gitignore`，保留硬编码路径

拒绝。虽然减少泄露，但新机器无法运行，且路径仍会暴露个人目录结构。

### 把 Vault 和凭证放入仓库加密保存

拒绝。会扩大密钥管理和误操作风险；本项目不需要也不应以仓库承载个人内容或会话凭证。

## 后果

- 新用户可先用 `demo_vault` 预览；接入真实数据时仍必须显式配置 Vault。
- 系统配置与计划任务不能靠克隆自动完成，需按操作手册在本机设置。
- 发布前仍需选择根许可证、复核 OCR 数据和第三方条款，并进行人工暂存审阅。
